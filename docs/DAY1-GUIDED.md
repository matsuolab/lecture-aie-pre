## S14

では、preDay 1の記録を追加していきましょう。
基準になる`master`へすぐに変更を入れる前に、今回の作業を分岐して進められるようにします。
このように、作業の流れを分けて進めるために使うのが、ブランチです。英語ではbranchと書きます。
実は、先ほどから基準にしている`master`も、ブランチの一つです。
今回は、この`master`から、新しく作業用のブランチを作ります。
今回のように、一つの目的のために作るブランチを、トピックブランチとも呼びます。
ここでは「preDay 1の学習記録を追加する」という目的で分けるわけです。

作業用のブランチで変更を記録していけば、`master`には作業を始める前の記録を残しておけます。
うまくいかなかったときにも、その記録と比べながら、何を直すかを考えられますね。
今回は一文ですが、複雑なプログラムを作るときにも、こうして基準の内容を残しながら変更を試せることが役に立ちます。

それでは、作業用のブランチを作ってみましょう。
ターミナルで、次の一行を実行してください。

```bash
git switch -c pre_day1/add-learning-record
```

（実行後）`pre_day1/add-learning-record`へ切り替わった、という表示が出ましたね。
これが、いま作ったブランチの名前です。
「preDay 1の学習記録を追加する」という作業が分かる名前にしています。

いま使った`git switch -c`は、新しいブランチを作り、そのブランチへ切り替えるための指示です。
これで、基準の`master`から、今回の作業用のブランチへ移りました。

## S18

では、その中のどの行が変わったのかも、見てみましょう。

その行の先頭に、`+`が付いていますね。

このように、変更前と変更後の違いを示したものを、差分と呼びます。
今回は、一文を追加しました。
差分にもその一文が出ているので、自分が行った変更と一致していますね。
記録を作る前には、こうして差分を見る習慣を付けておきましょう。

## S18A

文章の一部を書き換えた場合にも、元の行を取り除き、新しい行を加えた形で表示されます。

## S21A

コミットは、どこで区切ればよいのでしょうか。
今回は「今日の目標を追加する」という一つの目的で、コミットを作りました。
もし同時に、ページの見た目を直したくなったら、それは別のコミットにすると、後から変更の理由を追いやすくなります。

一つのコミットに、説明を一つ付けられるくらいのまとまりを考えてみてください。
「目標を追加した」と「見た目を直した」が分かれていれば、問題が起きたときも、どちらの変更を調べるか絞りやすいですね。
レビューする人も、一度に確認する範囲を小さくできます。
ただし、一行ずつ分ければよい、ということではありません。
同じ目的のために必要な変更はまとめて、一つの意味が通る単位で記録します。
これが、小さいコミットに分けるときの考え方です。
